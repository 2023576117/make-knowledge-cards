# Make Knowledge Cards

一个把文章变成知识卡片的 Skill。输入一段文章（直接粘贴的文本，或本地 `.md` / `.txt` 文件路径），输出 5–8 张 Markdown 知识卡片，每张只讲一个知识点。

适用于任何遵循 `agents/openai.yaml` 接口规范的智能体平台（OpenAI 等）。

## 它能做什么

- **输入**：粘贴的文章文本，或本地 `.md` / `.txt` 文件路径
- **输出**：5–8 张知识卡片，每张包含四个字段：
  - **标题（Title）** —— 一句话或一个短语，点出这个知识点
  - **核心知识（Core knowledge）** —— 知识点本身，用原文的话、按原文的力度陈述
  - **简明解释（Explanation）** —— 为什么成立 / 怎么运作，不引入原文没有的机制
  - **例子 / 自测问题（Example / Self-test）** —— 优先用原文自带的具体案例；没有案例时改成只用本卡就能回答的自测题

## 它不做什么（明确边界，不靠临场发挥）

- **不**抓取网页、不读取 URL 内容（请粘贴正文或存成文件）
- **不**支持 PDF / DOCX / EPUB / 图片 / 扫描件（请转成文本）
- **不**导出 Anki / CSV，也不接入任何记忆卡 App（只产出 Markdown）
- **不**提供图形界面（完全在对话里运行）
- 当来源根本不支持卡片（日记、转录稿、流水账）时，会诚实返回 `Cards: 0`，而不是硬凑

## 设计原则

1. **一卡一知识点** —— 一张卡需要 "and" 才能概括，就拆成两张；知识点数量优先于凑数。
2. **不编造** —— 任何原文没有的主张、数字、因果都不出现。解释只做"重述原文已说的因果""展开原文已说的后果""连接原文同段已有的两个事实"三种事之一。
3. **不抬高** —— 原文说"我 / 我的 / 我发现"，卡片不能写成普遍事实；原文是"我选择 / 应该用"，卡片不能写成"会 / 是"。
4. **去重** —— 意思重复的候选合并成一张更清楚的卡。
5. **信息不足就少做** —— 不足 5 个有效知识点就只出那些；来源零知识就返回 `Cards: 0`。

## 使用方法

把文章贴给支持本 Skill 的智能体，或给出本地文件路径，并说类似：

> 用 make-knowledge-cards 把这篇文章做成知识卡片

- 输入是**文件路径**时，扩展名必须是 `.md` 或 `.txt`；其它格式请先转文本。
- 卡片默认直接写在回复里；只有当你要求导出文件时，才会写入文件。

## 输入输出示例

**输入**（粘贴的一段技术短文，节选）：

> SQLite 的 WAL 模式下，写操作追加到 `-wal` 文件、不阻塞读；checkpoint 把 `-wal` 合并回主库。默认自动 checkpoint，但写入远超读取的高吞吐场景应手动调度 checkpoint，否则 `-wal` 文件无限增长。

**输出**：

```markdown
# Knowledge Cards: SQLite 的 WAL 模式

Source: pasted text
Cards: 2

---

## Card 1 — WAL 让写不阻塞读

**Core knowledge**: 在 WAL（write-ahead log）模式下，写操作追加到 `-wal` 文件，读仍读主库，因此写不会阻塞读。

**Explanation**: 读和写落在不同文件上，读进程无需等待写进程释放主库文件锁。

**Example**: 写操作只追加到 `-wal` 文件、不触碰主库，读操作继续读主库。

---

## Card 2 — 高吞吐写入要手动 checkpoint

**Core knowledge**: 默认自动 checkpoint，但写入远超读取的场景应手动调度 checkpoint，否则 `-wal` 文件会无限增长。

**Explanation**: 自动 checkpoint 的频率跟不上写入速度时，`-wal` 累积的未合并内容只会越来越多。

**Self-test**: 什么现象说明你需要从自动 checkpoint 改用手动 checkpoint？
```

**当来源不支持卡片时：**

```markdown
# Knowledge Cards: 1946-03-12 日记

Source: pasted text
Cards: 0

Note: 这是一篇文学日记，只记录日常片段和私人回忆，没有可独立提取的知识点；如需可改用摘要或时间线。
```
